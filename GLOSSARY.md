# GLOSSARY — словарь терминов проекта Stuff

> Единый словарь терминов проекта. **Незнакомый термин → сначала сюда** — дешевле, чем выводить смысл из кода.
> Термин определяется **только здесь**; доки ссылаются на словарь, а не переопределяют значение.
> Новый/изменившийся термин → добавить сюда и обновить дату «Сверено» (см. AGENTS.md, «Документация модулей»).
> Сверено: 2026-09-22

## Процесс и документация

| Термин | Определение | Источник |
|--------|-------------|----------|
| **LLM-wiki** | Живая документация, которую LLM-агенты читают и поддерживают при работе с кодом: AGENTS.md (правила) + ARCHITECTURE.md (roadmap) + модульные доки + этот словарь. | AGENTS.md |
| **Модульная документация** | `.md`-док рядом с кодом модуля (имя = имя модуля) с фиксированными секциями: Назначение и границы / Ключевые файлы / Инварианты и поток данных / Подводные камни и баги / TODO / Связанные доки. | AGENTS.md |
| **Дрейф доков** | Расхождение дока с кодом после изменений. Главный риск LLM-wiki: устаревший док хуже его отсутствия. Противодействие — правило сверки и команда `/wiki-sync`. | AGENTS.md |
| **Сверка** | Проверка дока затронутого модуля против кода после изменений; фиксируется строкой «Сверено: дата» в шапке дока. | AGENTS.md |

## Архитектура и слои

| Термин | Определение | Источник |
|--------|-------------|----------|
| **Слои (blib → beng → game)** | Строгая иерархия: `blib` — сервисы и платформенные примитивы (ноль игровых концепций); `beng` — среда выполнения (ECS, Application, модули, ресурсы); `game` — правила и контент конкретной игры. Нижний слой не знает о верхнем. | ARCHITECTURE.md |
| **lib + тонкий exe** | Паттерн: каждый исполняемый файл — тонкая `main()` над core-библиотекой; core даёт frame-API и **не владеет** главным циклом. | ARCHITECTURE.md |
| **Frame-API** | Интерфейс core-библиотеки для тонкого exe: `initialize`/`tick`/`shutdown` (+ `isRunning`). | ARCHITECTURE.md |
| **PIE (Play In Editor)** | Запуск игры внутри эдитора; единственный допустимый случай in-process хостинга сервера. | ARCHITECTURE.md |
| **Loopback** | Одиночная игра = локальный сервер + loopback-подключение; сервер всегда отдельный процесс (кроме PIE). | ARCHITECTURE.md |
| **Плагин-модель эдитора** | Один эдитор на все игры; игра подключается как DLL; типы компонентов регистрируются явно, per-scene, по стабильным именам. | ARCHITECTURE.md |
| **Стабильное имя компонента (`componentTypeName`)** | Статическое имя типа компонента (`static constexpr const char*`), по которому тип регистрируется и резолвится в сцене. `static`-локальные ID и `typeid()` через границу DLL запрещены. | BENG.md |

## blib

| Термин | Определение | Источник |
|--------|-------------|----------|
| **bootstrap exception** | Единственное место, где `GlobalAllocator` использует системный `::operator new/delete` и создаёт свои внутренние объекты напрямую (иначе самоссылка/нереентерабельность); помечается комментарием `// bootstrap exception`. | SYSTEM.md |
| **SAL-аннотации** | Обязательные аннотации параметров-указателей/ссылок: `_In` / `_Out` / `_In_opt` / `_Out_opt`. | AGENTS.md |
| **Branch hints** | Макросы `__blib_likely`/`__blib_unlikely` для подсказок компилятору; `__blib_unlikely` — для холодных веток проверок ошибок. | ERROR_HANDLING_ARCHITECTURE.md |
| **Enum-коды ошибок** | Ошибки возвращаются enum-кодами модуля (успех — `None = 0`, enum наследуется от `buint32`); фатальные — `__blib_fatal`. | ERROR_HANDLING_ARCHITECTURE.md |
| **`__blib_return_error`** | Макрос возврата ошибки: логирует в `Console` и делает `return <код>`. | ERROR_HANDLING_ARCHITECTURE.md |
| **GlobalAllocator** | Глобальный аллокатор — единственный источник динамической памяти проекта (`allocate`/`deallocate`). | SYSTEM.md |
| **DefaultAllocator** | Аллокатор по умолчанию: прокси к `GlobalAllocator`; в debug-сборке — `DebugAllocator` с guard bytes. | SYSTEM.md |
| **StdAllocatorAdapter** | Адаптер, подключающий blib-аллокатор к `std`-контейнерам; хранит указатель и **не владеет** аллокатором (аллокатор обязан жить дольше контейнера). | AGENTS.md |
| **SPSC / MPSC** | Lock-free очереди: single/multi-producer — single-consumer. | SYSTEM.md |
| **Intrusive free list** | Связный список свободных блоков, узел которого (`next`) хранится прямо в памяти самого блока — без отдельной аллокации под узел. В `PoolAllocator` используется для O(1) `allocate`; занятость блока для итерации определяется не по нему, а по инлайн-битмапу чанка (O(1)). | SYSTEM.md |
| **SBO** | Small buffer optimization (строки/контейнеры с встроенным малым буфером). | SYSTEM.md |

## beng

| Термин | Определение | Источник |
|--------|-------------|----------|
| **ECS** | Entity-Component-System: сущности (`EntityID`), компоненты в пулах, системы с приоритетами. | BENG.md |
| **ComponentPool** | Пул компонентов одного типа в сцене; итераторы `begin()/end()` обходят только активные компоненты (`isActive`), `*it` → `T&`, владелец — `it.getEntityId()`. | BENG.md |
| **Активный компонент (`isActive`)** | Флаг `IComponent::isActive` (по умолчанию `true`): неактивные компоненты пропускаются итераторами `ComponentPool`, но остаются в пуле и считаются в `size()`. | BENG.md |
| **ComponentType / ComponentMask** | `ComponentType` — локальный индекс типа в сцене (бит в `ComponentMask`, лимит 64 типа на сцену); регистрация — per-scene, до запуска цикла. | BENG.md |
