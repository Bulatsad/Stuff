# GLOSSARY — словарь терминов проекта Stuff

> Единый словарь терминов проекта. **Незнакомый термин → сначала сюда** — дешевле, чем выводить смысл из кода.
> Термин определяется **только здесь**; доки ссылаются на словарь, а не переопределяют значение.
> Новый/изменившийся термин → добавить сюда и обновить дату «Сверено» (см. AGENTS.md, «Документация модулей»).
> Сверено: 2026-09-28

## Архитектура и слои

| Термин | Определение | Источник |
|--------|-------------|----------|
| **Слои (blib → beng → game)** | Строгая иерархия: `blib` — сервисы и платформенные примитивы (ноль игровых концепций); `beng` — среда выполнения (ECS, Application, модули, ресурсы); `game` — правила и контент конкретной игры. Нижний слой не знает о верхнем. | ARCHITECTURE.md |
| **lib + тонкий exe** | Паттерн: каждый исполняемый файл — тонкая `main()` над core-библиотекой; core даёт frame-API и **не владеет** главным циклом. | ARCHITECTURE.md |
| **Frame-API** | Интерфейс core-библиотеки для тонкого exe: `initialize`/`tick`/`shutdown` (+ `isRunning`). | ARCHITECTURE.md |
| **PIE (Play In Editor)** | Запуск игры внутри эдитора; единственный допустимый случай in-process хостинга сервера. | ARCHITECTURE.md |
| **Loopback** | Одиночная игра = локальный сервер + loopback-подключение; сервер всегда отдельный процесс (кроме PIE). | ARCHITECTURE.md |
| **Плагин-модель эдитора** | Один эдитор на все игры: единый `beng-editor.exe` (каркас `EditorApplication`), игра подключается как DLL (gravelands.dll: extern "C"-фабрики create/destroy — единственная точка входа; этап 1 — статический линк того же кода); типы компонентов регистрируются явно, per-scene, по стабильным именам. Никаких эдиторов на игру (gravelands-editor и т.п.) нет. | ARCHITECTURE.md |
| **Стабильное имя компонента (`componentTypeName`)** | Статическое имя типа компонента (`static constexpr const char*`), по которому тип регистрируется и резолвится в сцене. `static`-локальные ID и `typeid()` через границу DLL запрещены. | BENG.md |

## blib

| Термин | Определение | Источник |
|--------|-------------|----------|
| **bootstrap exception** | Единственное место, где `GlobalAllocator` использует системный `::operator new/delete` и создаёт свои внутренние объекты напрямую (иначе самоссылка/нереентерабельность); помечается комментарием `// bootstrap exception`. | SYSTEM.md |
| **SAL-аннотации** | Обязательные аннотации параметров-указателей/ссылок: `_In` / `_Out` / `_In_opt` / `_Out_opt`. | AGENTS.md |
| **Branch hints** | Макросы `__blib_likely`/`__blib_unlikely` для подсказок компилятору; `__blib_unlikely` — для холодных веток проверок ошибок. | ERROR_HANDLING_ARCHITECTURE.md |
| **Enum-коды ошибок** | Ошибки возвращаются enum-кодами модуля (успех — `None = 0`, enum наследуется от `buint32`); фатальные — `__blib_fatal`. | ERROR_HANDLING_ARCHITECTURE.md |
| **`__blib_return_error`** | Макрос возврата ошибки: логирует в `Console` и делает `return <код>`. | ERROR_HANDLING_ARCHITECTURE.md |
| **GlobalAllocator** | Глобальный аллокатор — единственный источник динамической памяти проекта (`allocate`/`deallocate`). | SYSTEM.md |
| **DefaultAllocator** | Аллокатор по умолчанию: прокси к `GlobalAllocator`; в debug-сборке — `DebugAllocator` с guard bytes. | SYSTEM.md |
| **StdAllocatorAdapter** | Адаптер, подключающий blib-аллокатор к `std`-контейнерам; хранит указатель и **не владеет** аллокатором (аллокатор обязан жить дольше контейнера). | AGENTS.md |
| **SPSC / MPSC** | Lock-free очереди: single/multi-producer — single-consumer. | SYSTEM.md |
| **Intrusive free list** | Связный список свободных блоков, узел которого (`next`) хранится прямо в памяти самого блока — без отдельной аллокации под узел. В `PoolAllocator` используется для O(1) `allocate`; занятость блока для итерации определяется не по нему, а по инлайн-битмапу чанка (O(1)). | SYSTEM.md |
| **SBO** | Small buffer optimization (строки/контейнеры с встроенным малым буфером). | SYSTEM.md |

| **Column-major** | Раскладка матрицы в памяти: элементы столбца лежат подряд (`data[столбец][строка]`, offset = col·H + row). Родная раскладка OpenGL; матрицы проекта — column-major (см. CORE.md «Конвенция матриц»). | CORE.md |
| **Row-major** | Раскладка матрицы в памяти: элементы строки лежат подряд. Используется только при чтении `initializer_list` (первые W значений — первая строка) и в JSON-сериализации; в памяти проекта не используется. | CORE.md |
| **Column-vector конвенция** | Математика на векторах-столбцах: `v' = M · v`; композиция «родитель·ребёнок» = `M_parent · M_local`; трансляция 4x4 — в последней колонке. Единственная конвенция проекта (GLSL-шейдеры, ECS, графика). | CORE.md |
| **Row-vector конвенция** | Математика на векторах-строках: `v' = v · M`, трансляция — в последней строке. Использовалась graphics-слоем до 2026-09-25 (с компенсацией `GL_TRUE` при загрузке в GL); с тех пор запрещена. | CORE.md |

| **Type erasure** | Стирание конкретного типа за общим API; в blib-system — `Allocator` (SBO + `IAllocatorImpl`) и базовый интерфейс `ITypeErased` (куча через член-`Allocator` + fn-ptr деструктор) для наследников. | SYSTEM.md |
| **Ref-counting (Allocator)** | Разделяемое владение stateful-аллокатором: heap-контрольный блок (`SharedState`: атомарный счётчик + инстанс аллокатора), `share()` при копировании, последний владелец разрушает аллокатор и возвращает блок GlobalAllocator'у. Работает и для move-only аллокаторов. | SYSTEM.md |
| **Промоция (Allocator)** | Первое копирование stateful-`Allocator`: аллокатор переезжает из inline-хранилища обёртки в heap-контрольный блок, обёртка переключается в shared-режим. | SYSTEM.md |
| **IAllocatorAware** | Интерфейс владения аллокатором: класс-наследник обязан проводить все свои аллокации через член-`Allocator` (дефолт — `DefaultAllocator`); `setAllocator` вызывается до первой аллокации, конструкторы не аллоцируют. | SYSTEM.md |
| **ResourceManager** | Кеш владеемых ISaveLoadable-ресурсов по строковым ключам (blib-core): dedup по содержимому (MD5 сериализованной формы) + refcount-доступ; файлы/пути не трогает. | RESOURCE_MANAGER.md |
| **Слот ресурса (`ResourceEntry`)** | Запись кеша ресурсов: type-erased объект (ITypeErased) + тег типа + дайджест содержимого + intrusive refcount. | RESOURCE_MANAGER.md |
| **ResourceRef** | Хендл на слот кеша ресурсов: копия +1 к refcount, разрушение — release; «осиротевший» слот живёт до последнего ref'а. | RESOURCE_MANAGER.md |
| **datahash** | MD5 сериализованной формы ресурса (`save()` → `MemoryStream` → `Md5Hasher`): идентичность содержимого для dedup'а. | RESOURCE_MANAGER.md |
| **Dedup (ресурсы)** | Разделение одного слота кеша между разными ключами с одинаковым содержимым (дайджест + тег типа); ключ-дубликат перемапливается на канонический слот. | RESOURCE_MANAGER.md |
| **Commit (ресурс)** | «Опечатывание» слота кеша: вычисление datahash + регистрация в dedup-индексе; вызывается после наполнения объекта (native/процедурно) или внутри `preload`. | RESOURCE_MANAGER.md |

## beng

| Термин | Определение | Источник |
|--------|-------------|----------|
| **ECS** | Entity-Component-System: сущности (`EntityID`), компоненты в пулах, системы с приоритетами. | BENG.md |
| **ComponentPool** | Пул компонентов одного типа в сцене; итераторы `begin()/end()` обходят только активные компоненты (`isActive`), `*it` → `T&`, владелец — `it.getEntityId()`. | BENG.md |
| **Активный компонент (`isActive`)** | Флаг `IComponent::isActive` (по умолчанию `true`): неактивные компоненты пропускаются итераторами `ComponentPool`, но остаются в пуле и считаются в `size()`. | BENG.md |
| **ComponentType / ComponentMask** | `ComponentType` — локальный индекс типа в сцене (бит в `ComponentMask`, лимит 64 типа на сцену); регистрация — per-scene, до запуска цикла. | BENG.md |
| **Обязательный компонент** | Компонент, без которого сущность существовать не может: сцена регистрирует тип автоматически в конструкторе и создаёт компонент каждой сущности в `createEntity()` (в Stuff единственный обязательный — `TransformComponent`, typeId 0). Явные регистрация/добавление запрещены (fatal), удаление запрещено (fatal). | AGENTS.md |
| **Строгое сравнение (`strongCompare`)** | Бит-в-бит сравнение объектов: все значения класса совпадают; указатели сравниваются по содержимому (для `IStrongComparable`) или по null-состоянию (контекстные); циклы разрешает `CompareSession`; `operator==` возвращает `strongCompare`. | icomparable.h |
| **`CompareSession`** | Контекст одного сеанса строгого сравнения: множество пар указателей «в процессе сравнения» — защита от бесконечной рекурсии на циклических графах объектов. | icomparable.h |
| **Round-trip verify** | Валидация сериализации: `save()` → поток → свежий объект того же типа → `load()` → `strongCompare`. Готовая реализация — `blib::core::verifyRoundTrip<T>` (без RTTI, требует default-конструктор). | isaveloadable.h |
| **Контекстные указатели** | Поля-указатели на внешние объекты (`Scene*`, ассеты), которые `load()` не восстанавливает: не сериализуются, `strongCompare` сравнивает их по null-состоянию — standalone-verify = true, in-scene = false (строгая модель). | icomponent.h |
| **onLoaded** | Вторая фаза `Scene::load`: virtual-хук `IComponent::onLoaded(Scene&)`, вызываемый у каждого компонента после загрузки всех данных — восстановление контекстных связей (`ownerScene` у Transform, перепривязка аниматора, RM-перезагрузка модели по пути). Порядок вызовов — по возрастанию `ComponentType` (порядок регистрации): компонент с зависимым onLoaded регистрируется после источника. | icomponent.h |
| **Магия формата (magic)** | Фиксированная сигнатура в начале файла (`"JSON\0"`, 5 байт у сейва сцены): определение формата файла; несовпадение — `LoadStatus::UnknownFormat`. | sceneSaveFormat.h |
| **Рефлексия компонентов** | Описание полей компонента БЕЗ RTTI: статический `ComponentTypeDescriptor` (имя типа + `IComponentField`-поля с геттером/сеттером, `FieldValue` — type-erased значение), предоставляется `T::componentReflection()`, хранится сценой per-ComponentType. Из неё растут Inspector, диагностика, будущая репликация. | BENG.md |
| **CommandHistory** | История команд эдитора (undo/redo): команды создаются УЖЕ выполненными, undo/redo резолвят всё заново (протухшие ссылки пропускаются); лимит, redo-ветка обрывается новой командой. Команды: поле через рефлексию, TRS-снимок, сущности (create/destroy со снимками сериализацией), компоненты (add/remove). | BENG.md |
| **Gizmo-манипулятор** | Инструмент правки трансформаций в эдиторе (как в Unity): режимы W/E/R (Translate/Rotate/Scale), драг за стрелку/окружность с фиксацией оси в момент клика; hit-тесты — расстояние луч↔ось/луч↔окружность; подсветка hot-оси; изменения пишутся в CommandHistory. | BENG.md |
| **CommandPacket** | Сетевая команда игрока (клиент → сервер): входной вектор движения (moveX/moveZ); сервер не доверяет клиенту — применяет только к юниту игрока. | GRAVELANDS.md |
| **Snapshot** | Снапшот авторитетного состояния (сервер → клиент): номер тика + позиции юнитов; клиент интерполирует между двумя последними. | GRAVELANDS.md |
| **Интерполяция снапшотов** | Сглаживание позиций юнитов на клиенте: линейная интерполяция между двумя последними снапшотами по времени приёма (фактор клампится [0,1]). | GRAVELANDS.md |
| **PIE-хостинг** | Play In Editor: эдитор хостит сервер и клиент игры in-process, связь — настоящий loopback TCP (сетевой код-путь = продакшену); клиент в PIE — без собственного ImGui-контекста. | GRAVELANDS.md |
| **Сброс сцены (`Scene::reset`)** | Очистка данных сцены (сущности, пулы, кеш ресурсов) с СОХРАНЕНИЕМ реестра типов и списка систем; пулы пересоздаются фабриками; после reset сцена готова к `load()` или повторной постройке контента. В отличие от `clear()` (деструктор) — реестр не сносится. | BENG.md |
| **`EditorApplication`** | Игра-агностичный каркас эдитора (таргет `beng-editor-core`; единый exe — `beng-editor`): окно/FBO вьюпорта/орбитальная камера, ImGui (контекст, WndProc-хук, кадр), ECS-сцена с движковыми типами и системами, панели вьюпорта/консоли, раскладка панелей по зонам `PanelZone`, горячие клавиши. Хост (игра/инструмент) наследует каркас и переопределяет хуки `onInitialize/onInput/onSceneWillUpdate/onSceneDidUpdate/onUi/onEscapePressed` — зародыш `IGameModule`. | BENG.md |
