# GRAVELANDS — референсная игра (диаблоид)

> Слой: `game` (`src/misc/gravelands`). Шпаргалка по устройству игры: таргеты, камера, тайлы, таймстеп.
> Не дублирует правила проекта (`AGENTS.md`) и roadmap (`ARCHITECTURE.md`) — только ссылается.
> **Обновлять при любом изменении кода gravelands** (см. AGENTS.md, «Документация модулей»).

---

## Назначение и границы

- **Gravelands — диаблоид** в духе «Path of Exile 2 с графикой Stronghold»; стилистический ориентир клиента — Hades 2 (см. ARCHITECTURE.md и план NPR-пайплайна в TODO).
- Таргеты (паттерн «lib + тонкий exe», каждый exe — тонкая `main()` над core-библиотекой):

| Таргет | Тип | Содержимое |
|--------|-----|------------|
| `gravelands-common` | library (header-only, INTERFACE) | общие константы (`config.h`); позже — компоненты, пакеты, формулы |
| `gravelands-server-core` + `gravelands-server` | library + exe | авторитетная ECS-симуляция (Scene + TransformSystem), фикс. тикрейт 30 Гц |
| `gravelands-client-core` + `gravelands-client` | library + exe | представление: окно, изокамера, тайлы, ввод |

- Слои: клиент/сервер зависят от beng/blib; `gravelands-common` — только от blib-int/beng-core.
- Что НЕ в этом доке: правила кодирования (AGENTS.md), план развития (ARCHITECTURE.md), детали ECS (BENG.md), детали рендера (GRAPHICS.md).

## Инварианты и поток данных

### Таймстеп (гибридный)

- **Сервер** — авторитет: `serverCore::tick()` меряет реальное dt (`beng::Time`), копит в аккумулятор и шагает `scene.update(serverFixedDelta)` фиксированными тиками 30 Гц (`serverTickRate`/`serverFixedDelta` из `common/config.h`). Несколько тиков за кадр — норм (догон), неиспользованный остаток живёт в аккумуляторе.
- **Клиент** — переменный dt кадра (`beng::Time::getDeltaTime()`), рендер каждый кадр.
- Сетевой цикл (команды TCP → тик → снапшоты TCP → интерполяция) ещё не реализован — см. ARCHITECTURE.md.

### Клиент (ClientCore)

- Pimpl `ClientCoreImpl` скрывает графические типы blib; память — через `GlobalAllocator` + placement new, `shutdown()` симметрично возвращает (деструктор — страховка).
- Кадр `tick()`: `time.tick()` → `window.update()` → `Keyboard::update()` → Escape закрывает окно → `updateCamera(dt)` → `renderTarget.clear()` → отрисовка тайлов → `window.display(renderTarget)`.
- **Камера** (`blib::graphics::IsometricCamera`): ракурс фиксирован (pitch 55°, yaw 45°, FOV 30° — лёгкая перспектива); WASD двигает `target` камеры в плоскости земли по осям «forward/right» горизонтальной проекции взгляда; `Add`/`Subtract` — зум дистанцией. После любых изменений обязателен `camera.update()` — view-матрица сама не пересчитывается.
- **Тайлы** (`IsometricTileset`): сетка 10×10 квадратов 30×30 на плоскости XZ (y = 0), нормали всех вершин `(0,1,0)`. Ромб на экране — проекция, а не форма тайла. Один `Mesh` на всю сетку, шахматная текстура 10×10 (клетка = пиксель = тайл, UV-диапазон тайла — его ячейка).
- **Тестовая сфера-«персонаж»** (`blib::graphics::Sphere`, фаза 2 NPR-пайплайна): UV-сфера радиусом 25 в центре сетки (центр на y = радиус — стоит на земле), шахматная текстура 16×16 по UV (unlit-режим M показывает узор, toon — узор + свет). Материал — `ShadingMode::Toon` (мягкий свет), тайлы — `Unlit`.
- **Плоскости-«деревья»** (`blib::graphics::SpritePlane`, фаза 5, NPR-гибрид): 3 unlit-квада 40×70 с процедурной текстурой (ствол + крона на прозрачном фоне, `generateTreeImage()`), alpha-test 0.5 (жёсткие края), поворот к камере вычисляется в `initialize()`: направление **к** камере (`camera.getPosition() - getTarget()`), `yaw = atan2(-dir.x, dir.z)` (конвенция `rotateY`, см. SpritePlane), нога в земле (центр на половине высоты). Порядок кадра: тайлы → тени → плоскости → сфера (сортировка не нужна — depth-test).
- **Отладочное управление (клавиши):** `N` — раскраска нормалями (`RenderContext::showNormals`); `M` — переключение сферы unlit/toon; **стрелки** — азимут/элевация источника света; `[`/`]` — интенсивность; **F5** — консольная команда `hotreload` (перекомпиляция шейдеров с диска без перезапуска; алиас `reload_shaders`, регистрируются `registerGraphicsConsoleCommands()` в `initialize()`).
- **Оверлей** — полупрозрачное ImGui-окно в углу (без рамок/ввода, `drawOverlay()`): текущие параметры света/камеры + список клавиш. Паттерн вьювера: WndProc-хук + сцена → back-буфер (пост-пасс или `blitToBackbuffer`), ImGui поверх, затем `swapBuffers`.
- **Blob-тени** (`blib::graphics::BlobShadow`, фаза 7): мягкие полупрозрачные диски под сферой (r=30) и деревьями (r=16), процедурный радиальный градиент (`generateShadowImage()`), подъём над землёй 0.5 (без z-fighting), блендинг и отключение записи глубины — внутри `BlobShadow::draw`. Порядок кадра: тайлы → тени → плоскости → сфера.
- **Контур сферы** (`Material::outlineEnabled/outlineWidth/outlineColor`, фаза 8): inverted hull — второй проход раздутых задних граней плоским цветом (тёмная кайма, толщина 1.5 мир. ед.). Клавиша `O` включает/выключает. Статика и плоскости — без геометрического контура (обводка рисуется в текстурах).
- **Скелетная модель-«танцор»** (фаза 9, рендер-ECS): `resources\Hip Hop Dancing.fbx` (Mixamo, Y-up, встроенные текстуры) — ECS-сущность (`TransformComponent` + `SkinnedMeshComponent` + `AnimatorComponent`), системы `TransformSystem`/`AnimationSystem`/`RenderSystem` из beng-client. Масштаб 0.1 (~18 ед. сетки при росте ~180), позиция (0, 0, 60), поворот к камере (−45°, конвенция rotateY), первый клип зациклен и играет. NPR на всех мешах: Toon + контур 0.25. Тень-блob под моделью (r=8). Путь контента резолвится из cwd → каталога exe → подъёмом по родителям (`resolveContentPath`). Порядок кадра: тайлы → тени → плоскости → сфера → `scene.update(dt)` (модель) → пост → UI.
- **Пост-пасс** (`blib::graphics::PostProcess`, фаза 6): дымка по глубине (тёмная тонировка вдаль), color grading (lift/gamma/gain + saturation), виньетка. Гамма — 1.0 (конвейер пока не линейный: текстуры в sRGB, см. GRAPHICS.md TODO sRGB). Вход — color/depth-текстуры FBO сцены; клавиша `P` включает/выключает для сравнения. За пределами сетки фон заливается цветом дымки (depth = far).

### Сервер (ServerCore)

- Владеет `beng::Scene` и `beng::TransformSystem` (Scene хранит сырой указатель на систему — порядок полей важен: система объявлена после сцены, разрушается раньше).
- `initialize()`: регистрация типов компонентов (строго до цикла — реестр не thread-safe, см. BENG.md) + `time.reset()`.
- `tick()`: аккумулятор → `transformSystem.update(scene, serverFixedDelta)` столько раз, сколько тиков накопилось; heartbeat-лог раз в секунду симуляции (`tickCounter`/`lastHeartbeatSecond` — защита от повторных логов в кадрах без тиков).

## Подводные камни / известные баги

- **`IRenderTarget::clear()` игнорирует аргумент цвета** (blib, GRAPHICS.md): `clear(Color::Black)` сейчас ничего не решает, реальный цвет — дефолтный clear GL. Фон мира фактически чёрный, пока не починен.
- **Порядок выгрузки GL:** `ClientCoreImpl` объявляет окно → таргет → камеру → тайлы; разрушение в обратном порядке — тайлы (`Mesh`) умирают раньше таргета/окна, контекст GL ещё жив (см. GRAPHICS.md «Владение GL»).
- **Изокамера:** `moveTarget` двигает цель в мировых координатах — движение по диагонали (W+D) быстрее одиночного; для геймплея нужна нормализация в `updateCamera`. Дистанция кламплена `[5, 100000]`, pitch `[1, 89]` — вырождение `lookAt` исключено.
- **Шахматная текстура тайлов** — 1 пиксель на клетку с LINEAR-фильтрацией: на границах ячеек лёгкое «просачивание» соседнего цвета. Терпимо для отладки; при появлении настоящих тайловых текстур заменить.
- **Сервер:** heartbeat печатает в консоль каждый тик первой секунды — шумно на старте (терпимо, но держать в уме при подключении сетевого слоя).
- **Два процесса при одиночной игре** (клиент + локальный сервер, ARCHITECTURE.md) — сейчас сервер отдельным exe не запускается; интеграция не реализована.
