# SC2IMG — конвертер текстур Stronghold (TGX/GM1 → PNG/BMP/JPG)

> Слой: `game` (`src/misc/sc2img`). **Утилита-инструмент** (не игра, не эдитор): выгружает изображения проприетарных форматов серии Stronghold в открытые форматы картинок — плейсхолдеры для lamphold и разбор форматов.
> Не дублирует правила проекта (`AGENTS.md`) и roadmap движка (`ARCHITECTURE.md`) — только ссылается.
> **Обновлять при любом изменении кода sc2img** (см. AGENTS.md, «Документация модулей»).
> Сверено: 2026-10-01

---

## Назначение и границы

- **sc2img** — GUI-утилита + headless CLI для конвертации текстур Stronghold (серия игр Firefly Studios): вход `.tgx` (одиночное изображение) и `.gm1` (контейнер с палитрой и десятками кадров), выход `.png`/`.bmp`/`.jpg`.
- Интерфейс в духе старой утилиты **Stronghold Image Toolbox** (elfofthefire, 2007): открыть файл → **сетка-контактник кадров** (выкладка как `PictureFlowBox` тулзы) с выбором на экспорт → превью с зумом → экспорт выделенных/всех. Ячейка — **нативный размер изображения 1:1** (без масштабирования/квадратного растяжения, тайлы 30×16 не искажаются — как в Toolbox). Вкладка «Scene» каркаса (3D-вьюпорт) **подменяется** вкладкой «Images» (`setSceneTabView` — сцена утилите не нужна); стрелки ↑/↓/←/→ листают кадры для быстрого просмотра анимации; верхняя панель — 3 строки контролов (`setHostBarRows`).
- **Здания (`DataType::Building`) собираются в один композит на здание** (как `ImageArrayPanel` Toolbox): части группы кладутся по offsets, поверх — тайлы-ромбы (земля); одна запись = одно здание (см. «Композиция зданий»).
- **Write-back НЕ нужен** (согласовано с автором): замена/инжект изображений обратно в .gm1 не делается — только чтение и экспорт.
- **Копирайт:** текстуры Stronghold — копирайтные материалы Firefly Studios. Допустимы только как временные плейсхолдеры пет-проекта (вне git — см. LAMPHOLD.md «Инварианты»); до публичного показа заменяются собственными/свободными ассетами. Утилита сама файлы не хранит — работает с путями, заданными пользователем.
- Паттерн «lib + тонкий exe»: `sc2img-core` (загрузка/экспорт, без GUI), `sc2img-app` (GUI-хост каркаса эдитора), `sc2img` (тонкий exe). GUI и headless делят один core.
- Что НЕ в этом доке: правила кодирования (AGENTS.md), каркас эдитора и панели (BENG.md), рендер/текстуры (GRAPHICS.md), roadmap игры lamphold (LAMPHOLD.md).

## Инварианты и поток данных

### Слои и владение

- **`sc2img-core` зависит только от blib-graphics** (там живут парсеры и `Image`); beng не нужен. **`sc2img-app`** — от core + `beng-editor-core` (каркас `EditorApplication`). Нижние слои об утилите не знают.
- **Документ — чистые CPU-данные** (`Sc2imgDocument`: вектор `ImageEntry` = `Image` + метаданные заголовка GM1). Рендер-ресурсы (GL-миниатюры) живут только в GUI-impl.
- **Контейнеры** документа/миниатюр/маски — `StdAllocatorAdapter` + член-`Allocator` (объявлен ПЕРЕД контейнерами, канон из scene.h). Векторы, отдаваемые старыми парсерами (std-аллокатор), — граница со старым кодом, не переписываем.
- **GL-миниатюры** (`Texture::create(image, rc, clamp_to_edge)`): освобождаются в `shutdown()` ДО гашения каркаса (GL-контекст обязан их пережить); пересобираются при загрузке/смене playerColor.
- **Раскладка вкладки — адаптивная:** ширина превью — доля ширины области (0.38, минимум 12 строк шрифта), сторона ячейки сетки — **нативный размер изображения** (1:1, как в Toolbox; без ужимания), ширина слайдера зума — 6 строк, ширины/резервы контролов верхней панели — тоже в строках (формат 5, поле цвета 3.5, резерв под кнопки 10); пиксельных констант в раскладке нет (см. BENG.md — раскладка каркаса тоже в долях). Пустые зоны панелей каркаса не резервируются — вкладка занимает всю ширину окна. Перенос строк сетки — по фактической ширине ячейки (широкие кадры уходят на свою строку, при переполнении — горизонтальный скролл).

### Композиция зданий (`DataType::Building`)

- Кадры группируются по `part` (группа — от `part == 0` до следующего `part == 0`; в корректном файле ровно `subparts` частей) и собираются в **один композит** (алгоритм повторяет `ImageArrayPanel::SetImages` Stronghold Image Toolbox):
  - bounding box — по частям (`hOff + hStart`, `vOff` + размер) **и тайлам** (`tileX = hOff + hStart + (direction == Left ? −14 : 0)`, `tileY = vOff + baseHeight`); в Toolbox обрезка только по частям (лево-сдвинутый тайл может клипаться — этот дефект не воспроизводим);
  - части рисуются первыми, тайлы-ромбы (прозрачные углы) — **поверх** них (порядок слоёв как в Toolbox); прозрачные пиксели не пишутся;
  - холст обрезается по bbox; предел стороны 4096 (иначе пустая 1×1 + warning).
- Запись получает `sourceIndex` = индекс ПЕРВОЙ части группы (имя экспорта вида `_0023`) и `bakedOffsets = true` — align к ней не применяется (смещения уже запечены).
- Tile-only группы (у кадра нет TGX-части, `size == 512` — напр. `tile_workshops`) собираются из одних тайлов.

### Поток данных

```
.tgx/.gm1 ──> parsers::TGXFile/GM1File (blib-graphics; GM1 отдаёт images + tiles + headers)
          ──> Sc2imgDocument::load() → vector<ImageEntry> (CPU; Building — композиты)
          ──> GUI: GL-миниатюры + превью / headless: сразу exportAll()
          ──> exportAll(): canvas (align-box или сам кадр) + Image::update
          ──> stbi_write_png/bmp/jpg (stb_image_write)
```

### Правила имён и форматов

- Имена вывода: TGX — `<baseName><ext>`; GM1 — `<baseName>_NNNN<ext>` (4 цифры), NNNN = `ImageEntry::sourceIndex` (для зданий — индекс первой части группы). `<baseName>` — имя входного файла без каталога и расширения.
- **PNG** (дефолт) и **BMP** (32 bpp с альфой) хранят прозрачность; **JPEG** — нет (альфа отбрасывается, warning при экспорте).
- **align по offset'ам** (`--align` / чекбокс): кадры вписываются в общий bounding box набора по `horizontalOffset`/`verticalOffset` заголовка GM1 (`Image::update` на прозрачный canvas) — кадры анимаций не «дёргаются». Без align — кадр как есть. Композиты зданий (`bakedOffsets`) в align-box не входят и не паддятся.
- **playerColor**: палитра GM1 сегментирована по игрокам (256 цветов на игрока). Дефолт — палитра 0 (нейтральная); `GM1File::playerColorOverridden/playerColorOverride` переопределяет глобально (UI-выбор/`--player-color`). В заголовке кадра цвета игрока НЕТ (`performanceId` — не цвет).
- Файл или папка входа различаются через Win32-атрибуты (`GetFileAttributesA`), НЕ через `Folder` (его конструктор «поднимается» от не-папок вверх).

### Ошибки

- `Sc2imgError : buint32 { None = 0, InvalidArgs, OpenFailed, ParseFailed, NoImages, ExportFailed }` — enum-коды по ERROR_HANDLING_ARCHITECTURE; логи `__blib_log_*`; headless возвращает 0/1 по счётчику ошибок.

## Подводные камни и баги

- **Формат GM1 выверен по референс-декомпилу** Stronghold Image Toolbox (ilspycmd, см. GRAPHICS.md «Форматы»): до сверки парсер читал заголовок со сдвигом на 4–8 байт и считал offsets абсолютными — мусорные размеры кадров доходили до `Image::create` → `std::length_error`/`bad_alloc` → «исключение» при открытии файла. Offset-таблица GM1 — **относительные** смещения от начала блока данных; поля `color`/`tileOffset` старого парсера оказались `performanceId`/`baseHeight`.
- **Типы данных кадров разные** (по Data_Type): 1/4/6 — 16-бит RGB555 в токенах; 2 — индексы палитры; 3 — тайл-ромб 30×16 + TGX-часть здания; 5/7 — raw 16 бит (`w×(h−7)` / `w×h`). Проверено на 199 файлах Crusader Extreme.
- **Валидация входных данных обязательна**: quantity/стороны кадров/offset+size лимитируются (см. gm1.cpp) — битые файлы дают пропуск кадра (пустой 1×1), а не исключение (проект исключениями не пользуется).
- **Стрелки листают кадры только без текстового ввода**: гейт `ImGui::GetIO().WantTextInput` (иначе клавиши перехватывались бы у поля пути в верхней панели); удержание клавиши даёт автоповтор, прокрутка сетки к выбранному кадру — флагом `scrollToPreview` (`SetScrollHereY`).
- **Композиция зданий читает const-срез `Image[x][y]`** — при первом использовании вскрылся латентный баг blib-core: `UnsafeSlicer::operator[]() const` рекурсивно звал сам себя (stack overflow); починен (см. CORE.md).
- **`blib::core::Folder::getAllEntries`** требует путь с ХВОСТОВЫМ слэшем (маска `path*`) и возвращает `.`/`..` — оба факта учтены в `processFolder` (нормализация + пропуск).
- **stbi_write_jpg не принимает stride** — для JPEG строится плотный RGB-буфер (`flattenRgb`), альфа отбрасывается.
- **Каталог вывода должен существовать**: stb пишет через `fopen` — ошибка, если папки нет (headless: `--out` создавать самому).
- **Порядок тейкдауна**: текстуры → вкладка/impl → каркас (иначе GL-утечки/краш при закрытии).
