# RESOURCE_MANAGER — blib-core/resource

> Слой: `blib-core`. Кеш владеемых ISaveLoadable-ресурсов с dedup по содержимому и refcount-доступом.
> Шпаргалка по инвариантам и граблям. **Обновлять при изменениях кода модуля** (см. AGENTS.md, «Документация модулей»).
> Сверено: 2026-09-24

---

## Назначение и границы

- `blib::resource::ResourceManager` — **кеш владеемых ресурсов**: хранит загруженные объекты по строковым ключам, разделяет одинаковое содержимое (dedup) и управляет временем жизни через intrusive refcount.
- **Требование к типу ресурса:** `ISaveLoadable` (сериализация + сравнение) **и** `IAllocatorAware` (аллокатор объекта) **и** статический тег `T::resourceTypeName` (стабильное имя типа; сравнение — по содержимому строки, не по адресу литерала — литералы из разных DLL не мержить по адресу). Реализовано для всех сериализуемых ассетов blib-graphics (см. GRAPHICS.md).
- **RM не трогает файлы и пути**: загрузка контента — на вызывающем (native `loadFromFile` у типа или сериализованный поток через `preload`). Резолв путей остаётся в game-слое.
- Идентичность содержимого — **MD5 сериализованной формы** (`save()` → `MemoryStream` → `Md5Hasher`, 16 байт). GL-состояние не сериализуемо → в хэш не входит (это и требуется: dedup по CPU-содержимому).
- Не в этом доке: устройство аллокаторов (`../system/SYSTEM.md`), сериализация ассетов (`../graphics/GRAPHICS.md`).

## Инварианты и поток данных

### Владение и счётчики

- **Слот (`ResourceEntry`)** выделяется RM'ом из `resourceAllocator` (placement new), живёт по фиксированному адресу, некопируем/неперемещаем. Erased-объект внутри — `ITypeErased` (fn-ptr деструктор).
- **refCount = число ключей в `entries` + число живых `ResourceRef`.** Ключ и каждый ref держат +1. `release()` при нуле уничтожает слот: erase из `byData` → `~ResourceEntry` (уничтожает erased-объект и его память через его аллокатор) → deallocate слота.
- **Инвариант жизни:** `ResourceRef`'ы обязаны умереть раньше своего RM. Деструктор RM = `unloadAll()`; слот, переживший снятие всех ключей, — утечка внешних ref'ов → **fatal** (abort). Ref после смерти RM — UB.
- `unload(key)` снимает только ключ: внешние ref'ы продолжают держать «осиротевший» слот (память освобождается при последнем release). Орфан остаётся в `byData` — будущий preload того же содержимого сделает dedup прямо на него.

### Поток construct → commit/preload

1. `construct<T>(key, args...)` — дубль ключа: warning + ref на существующий (идемпотентно). Иначе: свежий слот → `emplace<T>` (тег + базовые указатели `ISaveLoadable`/`IAllocatorAware` атомарно) → `setAllocator(resourceAllocator)` (**копия = share**: все ресурсы делят один impl) → вставка в `entries` (+1 ref ключа) → ref (+1).
2. Наполнение — вызывающим: `rf.get<T>()` → native/процедурная загрузка, либо `preload(rf, is)` = `load(is)` + `commit`.
3. `commit(rf)` — «опечатывание»: MD5 save-формы → dedup по `byData[(digest, typeName)]`:
   - **дубль** — ключ источника перемапливается на канонический слот (+ref каноническому, −ref свежему), возвращается **ref на канонический**; свежий слот живёт только ref'ами вызывающего и умрёт после переприсваивания. Паттерн: `rf = rm.commit(rf);`
   - **промах** — регистрация в `byData`, возвращается тот же слот.
   - идемпотентен (`committed` — без перехэширования); провал save/hash — warning, слот остаётся не-«опечатанным» (в dedup не участвует).
4. `preload` при провале `load` — слот снимается с кеша (unloadEntry), возвращается пустой ref; ref вызывающего держит орфан.

### Хранилище

- `entries`: `unordered_map<ResourceKeyString, ResourceEntry*>` — строковый ключ с `StdAllocatorAdapter<char>` (канон scene.h); map хранит только указатели → слоты стабильны.
- `byData`: `unordered_map<ResourceDataKey, ResourceEntry*>` — (MD5, тег типа) → канонический слот; тег сравнивается по содержимому (`strcmp`).
- Ключи RM — `std::string` на входе (внутри перекладываются в `ResourceKeyString` через `containerAllocator`). `get` — не на горячем пути (взял `T*`/ref один раз — дальше кешируй).

## Подводные камни и баги

- **`*/` внутри док-комментариев** закрывает комментарий раньше времени (был баг в resourceEntry.h при написании) — в комментариях не использовать конструкции вида `T*` после `/`.
- `ResourceEntry::release()` при нуле уничтожает слот **через `owner`**: RM обязан пережить все свои слоты; ref'ы обязаны умереть раньше RM (см. fatal выше). Доступ к полям слота после `release()` — use-after-free (в unloadAll проверка утечки делается ДО снятия ключевых ref'ов).
- MD5 — криптографически устарел, но для dedup по содержимому ассетов коллизии практически невероятны; dedup-ключ всё равно композитный (digest + тег типа).
- `Allocator`-копия в `setAllocator` — share: stateful-состояние разделяется всеми ресурсами (после фикса ref-counting 2026-09-24 — корректно). Независимые аллокаторы на ресурс невозможны для move-only impl (`clone()` даёт «мёртвый» аллокатор) — и не нужны.
- **Вложенные ресурсы** (SkinModel → Mesh → Image) имеют собственные аллокаторы: `setAllocator` на корне не пропагируется (см. GRAPHICS.md, «Долг»). При v1-аллокаторе (DefaultAllocator) источник памяти у всех один.
- `construct`-идиомпотентность: второй `construct` по занятому ключу молча игнорирует переданные ctor-аргументы.
- Не thread-safe (как `ComponentPool`): все операции — на одном потоке.
