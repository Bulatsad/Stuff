[патч 5] детальные сообщения об ошибках
файлы: impl/pdl.cpp, src/test/src/impl/testpdl.cpp

- многострочный формат ошибок: expected ... at '::узел' + but got ...
  + позиция во входной строке (token N/M, byte offset, line:col)
- InTok/tokenize: входные токены получили line/col
- matchNode: при жадном отказе добавляется строка "alternative at
  '::узел' failed after consuming N token(s)"; если ни одна альтернатива
  не совпала без потребления - сводка "no alternative matched" с
  причинами по каждой (сначала совпавшие по guard'ам, потом отсеянные;
  guard-причина: какой guard, что захвачено / not captured)
- попутно починен предсуществующий баг подсчёта потребления: Field и
  Optional при провале не продвигали позицию состояния (commit-счётчик
  и furthest-position в MatchResult теперь корректны)
- assignBindings: ошибки с типами (type 'list' vs 'string') и путём
  привязки; variable not captured - с путём привязки
- trailing input: сколько токенов осталось + первый лишний с позицией
- loader: ошибки последовательностей с именем узла
- тесты: усилены проверки содержимого ошибок, новые кейсы
  "PDL demo1/demo2: error message details", итого 156
- standart.txt: раздел 10 "ОШИБКИ"

[патч 4] фикс: захват одноэлементной последовательности
файлы: impl/pdl.cpp, demo1.pdl, src/test/src/impl/testpdl.cpp

- matchAlt: последовательность из одного элемента теперь отдаёт значение
  самого элемента, а не список - узел "= __any;" захватывается как string,
  и его можно биндить к скалярной переменной (было: AnyList, скалярная
  переменная падала с "cannot assign captured value to variable")
- новая семантика: узел захватывает значение единственного элемента,
  иначе список значений элементов (standart.txt обновлён)
- demo1.pdl: корень теперь ::CommandTemplate: ::SingleWord <globalTemplate>;
  (::SingleWord - обязательный первый элемент каждой команды), добавлены
  let var string @word; и @word = ::SingleWord; - скалярный захват __any
  проверяется в каждом парсе demo1
- тесты: все входы demo1 дополнены первым словом (exe/exe1/exe2),
  новый кейс "PDL demo1: __any scalar binding"
- demo2.pdl: GCommand с ExePath = __any (скалярный захват exepath);
  тест "PDL demo2: __any" починен (parse успешен, а не фейлится) +

[патч 3] wildcard-элемент __any
файлы: impl/pdl.cpp, demo1.pdl, src/test/src/impl/testpdl.cpp

- новый встроенный элемент __any: матчит ровно один произвольный токен
- терминатор (объявленный) и конец ввода __any НЕ ест - при встрече с ними
  обычный fail с нулевым потреблением (в [__any] просто пропускается),
  hard-error из-за __any невозможен (потребление всегда 0 или 1)
- захват __any - текст токена как string (можно биндить к @var)
- demo1.pdl: команда "one" - flagName "any"/"skip", flagValue = ::SingleWord
  и [::SingleWord], где ::SingleWord: __any;
- тесты: 4 новых кейса (одиночный токен, optional skip, parseNext через
  терминатор, fail на терминаторе/EOS), итого 151

[патч 2] v2: guard-блоки, явный терминатор, parseNext
файлы: impl/pdl.cpp, pdl.h, demo1.pdl, src/test/src/impl/testpdl.cpp

- лексер: блочные комментарии /* ... */ (без вложенности, незакрытый - ошибка
  лексера), новые токены { и }
- guard-блоки: после цепочки [guard] можно писать { ... }; guard'ы применяются
  ко всем определениям внутри блока, вложенность разрешена, цепочка guard'ов
  (последовательные и вложенные) работает как AND
- объявление терминатора: "lit" = __terminator; (литералы через запятую,
  одно объявление на файл, дубликат - ошибка загрузки)
- __terminator матчит явный токен ИЛИ конец ввода (последняя команда без
  терминатора - ок)
- __everything = все токены до терминатора (не включая его) или до конца ввода
- API: bool parseNext(const std::string& text, size_t& offset) - парсит одну
  команду с байтового offset, после успеха сдвигает offset за съеденный
  терминатор (или на text.size()); vars сбрасываются в начале каждого вызова;
  false при конце ввода возвращается БЕЗ ошибки; защита от нулевого
  потребления (иначе бесконечный цикл у вызывающего)
- фикс: захваты вложенных узлов всплывают вверх (matchElem Field теперь
  мержит внутренние captures), иначе привязки @var к узлам внутри подправил
  не находились
- фикс: MatchState.terms пробрасывается в Field-потомков, иначе __everything
  внутри вложенных узлов не видел терминатор
- demo1.pdl: commandArgs = __everything (было __everything __terminator -
  внутренний терминатор съедал "|" и ломал шаблон; одиночный parse() при
  этом работал - поэтому выглядело как баг parseNext)
- тесты: 9 новых кейсов в testpdl.cpp (итого 147), все зелёные, 10 прогонов
  подряд стабильны

отложено (вопросы, поднятые при обсуждении):
- переопределение/удаление терминаторов (сейчас дубликат - ошибка)
- else-ветки guard-блоков
- кэширование токенизации в parseNext (сейчас токенизируется весь текст
  на каждый вызов - O(n) на команду)

[патч 1] реализация v1
(перенос из readme.txt, раздел "реализация v1")

типы: string, int, float, bool, array<T> (вложенные array запрещены).
литералы в .pdl типизированы: "..." - string, 1 - int, 1.5 - float, true/false - bool.
соответствие входного токена литералу - точное сравнение текста ("01" не равно 1).

bool принимает ТОЛЬКО "true"/"false". никаких "1"/"0" и неявных преобразований.

"=" и "+=" оба добавляют альтернативу узлу (повторные определения не заменяют старые).
охранники [path == литерал] применяются к альтернативе, перед которой стоят.
проверка охранника: последний захват узла path в текущей цепочке парсинга
(включая объемлющие правила). совпадение - точное сравнение текста.

семантика парсинга - жадная, без откатов:
- альтернативы узла пробуются по порядку;
- альтернатива, которая потребила хотя бы один токен и провалилась, сразу даёт ошибку
  (остальные альтернативы не пробуются);
- необязательная часть [...] пропускается только если не совпала ни одного токена,
  иначе ошибка (поэтому "add signed true" не парсится);
- ссылка узла на самого себя последним элементом = повторение (эквивалент [...]).

__terminator - конец входной строки, __everything - все оставшиеся токены.
парсинг успешен только если корневое правило съело весь ввод.
корневое правило - первое правило файла.

переменные: let var <тип> @имя; привязка: @имя = ::путь;
захват берётся из области видимости корневого правила.
если привязка не была захвачена: для array - пустой массив, для скаляра - ошибка.
типы захвата и переменной должны быть совместимы:
- string <- любой скаляр (как исходный текст);
- int <- int или строка-целое; float <- float/int или строка-число;
- bool <- только "true"/"false";
- array<T> <- только список совместимых значений.

левая рекурсия определяется при загрузке (цикл по первым элементам альтернатив),
плюс страховка по глубине рекурсии во время парсинга.
литералы в последовательностях напрямую не разрешены - только через поля.
