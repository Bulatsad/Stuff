============================================================
PDL - стандарт языка (версия 2)
============================================================

PDL (Parser Description Language) - декларативный язык описания парсеров
для движка Stuff. Файл .pdl описывает грамматику, по которой входная
строка раскладывается в переменные, доступные из C++ через blib::pdl::Parser.

1. ЛЕКСИКА ГРАММАТИКИ

1.1. Комментарии
    // до конца строки
    /* блочный комментарий, без вложенности */
    незакрытый /* - ошибка загрузки.

1.2. Токены
    :: < > [ ] { } = += == , ; @ "..." числа идентификаторы
    Ключевые слова (идентификаторы): let var array string int float bool
    true false __terminator __everything __any

1.3. Литералы типизированы:
    "..."  - string
    1      - int
    1.5    - float
    true / false - bool

2. СТРУКТУРА ФАЙЛА

2.1. Объявления переменных (linkage):
    let var string @command;
    let var array<string> @options;
    имя переменной уникально, повторное объявление - ошибка.

2.2. Объявление терминатора (необязательно):
    "|" = __terminator;
    литералы через запятую: "|",";" = __terminator;
    одно объявление на файл, дубликат - ошибка загрузки.
    без объявления __terminator = только конец ввода.

2.3. Правила (узлы). Путь узла: ::Имя::<поле>::<поле>...
    первое правило файла - корневое (точка входа парсинга).
    объявление узла: ::CommandTemplate: <globalTemplate>;
    определения альтернатив:
        ::узел = ...;   - добавить альтернативу
        ::узел += ...;  - то же самое (синоним)
    повторные определения НЕ заменяют старые - добавляют.

2.4. Привязки переменных:
    @command = ::CommandTemplate::<globalTemplate>::<command>;
    имя переменной должно быть объявлено через let var,
    повторная привязка - ошибка.

3. АЛЬТЕРНАТИВЫ

3.1. Набор литералов: "get","set" / 1,2 / true,false

3.2. Последовательность: элементы через пробел:
    <поле>       - поле текущего узла
    ::путь       - ссылка на другой узел
    [ ... ]      - необязательная часть
    __terminator - явный терминатор или конец ввода
    __everything - все токены до терминатора (не включая) или до конца
    __any        - ровно один произвольный токен (кроме терминатора/EOS)
    литералы напрямую в последовательностях запрещены - только через поля.

4. GUARD'Ы (условные определения)

    [::узел == литерал] - условие на последний захват узла в текущей цепочке
    парсинга (включая объемлющие правила). сравнение - точное по тексту.

    [g1] [g2] ::узел = ...;   - AND-цепочка, применяется к следующему
                                определению
    [g1] { ... }             - блок: guard'ы применяются ко ВСЕМ
                                определениям внутри, вложенность разрешена,
                                guard'ы вкладываются по AND
    блок без guard'ов { ... } - просто группировка (guard'ы не добавляет)

5. СЕМАНТИКА ПАРСИНГА (жадная, без откатов)

- альтернативы узла пробуются по порядку;
- альтернатива, потребившая хотя бы один токен и провалившаяся, даёт
  ошибку немедленно (остальные не пробуются);
- [...] пропускается только при нулевом потреблении, иначе ошибка;
- __any ест ровно один токен и никогда не ест терминатор/EOS; при встрече
  с ними - обычный fail с нулевым потреблением (в [...] просто
  пропускается), hard-error невозможен;
- ссылка узла на самого себя последним элементом = повторение;
- левая рекурсия запрещена: проверяется при загрузке (цикл по первым
  элементам), плюс страховка по глубине (лимит рекурсии при матче).

6. ВХОДНАЯ СТРОКА

- разбивается на токены по пробелам;
- терминатор - отдельный пробелоразделённый токен:
  "varVal1 | set" - ок, "varVal1|" - нет;
- конец ввода всегда терминирует (последняя команда может быть без
  терминатора).

7. ПЕРЕМЕННЫЕ И ЗАХВАТЫ

- захват @var берётся из области видимости корневого правила;
- значение захвата узла: набор литералов - скаляр; последовательность из
  одного элемента - значение этого элемента; из нескольких - список
  значений элементов;
- привязка не была захвачена: array - пустой массив, скаляр - ошибка;
- совместимость типов:
    string <- любой скаляр (как исходный текст);
    int    <- int или строка-целое;
    float  <- float/int или строка-число;
    bool   <- ТОЛЬКО "true"/"false";
    array<T> <- список совместимых значений;
- типы: string, int, float, bool, array<T> (вложенные array запрещены).

8. C++ API (blib::pdl::Parser, см. blib/pdl/pdl.h)

    bool load(const std::string& path);
        загрузить грамматику; false + getLastError() при ошибке.

    bool parse(const std::string& text);
        разобрать ВЕСЬ ввод одной командой. с явным терминатором
        "get safe false |" - ок, "a | b" - ошибка trailing input.

    bool parseNext(const std::string& text, size_t& offset);
        разобрать ОДНУ команду с байтового offset; после успеха offset
        сдвигается за съеденный терминатор (или на text.size());
        переменные сбрасываются в начале каждого вызова;
        возвращает false БЕЗ ошибки когда ввод закончился - это
        нормальное окончание цикла:
            size_t off = 0;
            while (p.parseNext(text, off)) { p.getVar(...); }

    template<class T> bool getVar(const std::string& name, T& out) const;
        T: std::string, bint32, float, bool и их std::vector<...>.

    const std::string& getLastError() const;

10. ОШИБКИ

    формат ошибок парсинга - многострочный, getLastError() возвращает весь
    текст целиком:

        parse error: expected 'yes', 'no' at '::...::<flagValue>'
          but got 'maybe' (token 4/5 'maybe' (byte offset 14, line 1:15))
          alternative at '::...::<options>' failed after consuming 1 token(s)

    составляющие:
    - expected ... at '::узел' - что ожидалось и в каком узле грамматики;
    - but got '...' / but input ended / but found terminator '|' /
      but found end of input - что реально пришло;
    - (token N/M, byte offset B, line L:C) - позиция во входной строке;
    - alternative at '::узел' failed after consuming N token(s) - жадный
      отказ: альтернатива уже начала матчиться и провалилась;
    - no alternative matched at '::узел' + причины по каждой альтернативе
      (сначала те, чьи guard'ы прошли, потом отсеянные guard'ами):

        parse error: no alternative matched at '::GCommand::<CommandArgs>'
          alternative 1: guard '::GCommand::<Command> == "move"' failed:
                         captured 'stop'
          alternative 2: guard '::GCommand::<Command> == "jump"' failed:
                         captured 'stop'

    - ошибки привязок: типы значения и переменной + путь привязки:

        cannot assign captured value of type 'list' to variable '@exe'
        of type 'string' (binding '::GCommand::<ExePath>')

        variable '@word' was not captured (binding '::SingleWord')

    - trailing input: сколько токенов осталось + первый лишний с позицией;
    - ошибки загрузки .pdl: строка грамматики + имя узла.
